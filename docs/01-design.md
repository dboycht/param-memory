## 1. 总览

```
              ┌────────────────────────────────────────────┐
   对话流 ──▶ │  写入判据（surprise / 信息增益）            │
              └───────────────┬────────────────────────────┘
                              │ 触发
                              ▼
              ┌────────────────────────────────────────────┐
              │  Write：k 步梯度，仅更新一个秩块（slot）     │
              │  + KL 锚定（对写前记忆状态的 KD/KL 约束）    │
              └───────────────┬────────────────────────────┘
                              ▼
   ┌──────────────┐   ┌───────────────────────────┐
   │ 槽位元数据   │◀─▶│  记忆载体：rank-blocked LoRA │──▶ 持久化到磁盘
   │ 效用/时间戳  │   │  W = W0 + (α/r) B A        │     （跨会话）
   └──────┬───────┘   └───────────┬───────────────┘
          │ 效用/时间                │ 前向隐式生效
          ▼                        ▼
   ┌──────────────┐        ┌──────────────────┐
   │ Forget：淘汰/  │        │ Read：查询 q → 答案│
   │ 衰减/精确擦除  │        │ （q 不含记忆内容） │
   └──────────────┘        └──────────────────┘
```

**主干全程冻结**；所有可写状态都在旁路 $\Delta$ 与槽位元数据里。

## 2. 记忆载体：rank-blocked LoRA

- 目标模块（与主流程解耦，可配置）：`q_proj, k_proj, v_proj, o_proj`（注意力）为默认；
  MLP 是否加入由消融决定（MLP 承载更多事实性知识，但代价与干扰都更大）。
- 总秩 $R = K \cdot r$；第 $k$ 槽占用秩索引区间 $[(k-1)r, kr)$。
- 前向：$h = W_0 x + \frac{\alpha}{r} \sum_{k \in \text{active}} B_k A_k x$。
- **写入**：冻结其它槽的参数，只对第 $k$ 槽做 $n_{\text{step}}$ 步梯度下降。
- **遗忘（精确擦除）**：$B_k \leftarrow 0$（并清空该槽元数据）。
  - **可验证性**：擦除后同一查询的输出必须**逐比特退化**到"该槽从未写过"的状态（若 A 也重置），
    这是 T2 的一条硬断言。
- **可归因性**：单槽开/关即可测"某条记忆对某查询的贡献"。

### 2.1 为什么不用稠密单适配器做对照

稠密适配器（单一 LoRA）无法定义"第几条记忆"，遗忘只能是软衰减，且无法做**单条记忆的因果消融**。
T1/T2 会保留"稠密适配器"作为一个 baseline 臂，用来证明**槽位划分不是装饰**。

## 3. 写入判据（Write）

**问题**：对话里没有标签告诉我们"什么该刻成钢印"。

**候选判据（T1 先用 a，T2 起做对照）**：

| 代号 | 判据 | 说明 |
| --- | --- | --- |
| (a) | **惊讶度** $s = -\log p_{\theta+\Delta}(m \mid x_{<t})$ | 与 Titans 的 surprise 同源；超阈值才写 |
| (b) | 显式指令 | 用户说"记住…" |
| (c) | 信息增益 | 写前/写后对一组探针的似然差 |
| (d) | 全写 | 作为上界 baseline（写入成本最大） |

**写入损失**：
$$\mathcal{L}_{\text{write}} = \underbrace{\text{CE}(m \mid \text{mem\_prompt}(q_m))}_{\text{教会可检索的问答对}} + \lambda_{\text{kl}} \underbrace{D_{\text{KL}}\big(p_{\theta+\Delta_{\text{old}}} \,\|\, p_{\theta+\Delta_{\text{new}}}\big)}_{\text{别忘掉已有记忆}} + \lambda_{\text{cap}} \underbrace{\text{CE}(\text{cap\_probe})}_{\text{别伤基座能力}}$$

- 第一项：写入时把记忆项构造成「查询 → 答案」对（查询由模板从 $m$ 生成），
  使读取时能凭查询键召回；**这是"可检索性"的来源**。
- 第二项：对**写前状态**的 KL 锚定 —— 旁路版 EWC/蒸馏，保护既有记忆槽与基座行为不被覆盖。
- 第三项：一小撮**基座能力探针**（固定通用样本）参与训练，抑制灾难性遗忘。

### 3.1 λ_cap 的具体实现：零空间投影（采纳 AlphaEdit 的思路）

文献侦察（分支 B）给出了一条**性价比最高**的"写进去不弄坏基座"手段：
**AlphaEdit（ICLR 2025 Oral, arXiv:2410.02355）**把权重扰动**投影到"待保留知识"的零空间**，
理论上保证保留知识的输出不变（报告平均 +36.7%，实现只需一行投影）。

- 在本项目里，被保留的对象 = **其它槽已写入的记忆 + 一小撮基座能力探针**；
- 做法：对写入梯度 $\Delta W_k$ 做投影 $P \Delta W_k$，$P$ 为保留键协方差零空间的投影矩阵；
- ⚠️ **已知局限（必须写进论文 limitation）**：零空间维数有限，编辑/记忆条数增多会**耗尽**，
  于是"零空间容量"与"槽位容量 $K$"耦合在一起 —— 这正好是 T2 容量实验里要单独量的一个量。

### 3.2 必须监控的量（文献指出的真实风险）

| 量 | 为什么监控 | 来源 |
| --- | --- | --- |
| **被更新矩阵的范数增长** | 连续编辑退化被归因于激活过度优化 + 被编辑矩阵范数持续增长；任何持续写参数的机制都必须盯住它 | arXiv:2502.01636 |
| **槽间串扰** | 协议 P4 的 `MEM_SHUFFLE` 臂：只开其它槽时是否也能答对 | 本项目协议 |
| **基座能力漂移** | 小模型比大模型遗忘更严重（方向性结论）⇒ 1.7B 上风险更高，必须逐轮测 | 分支 B §5.2（二手，未核实数字） |

> ⚠️ 上面第 3 条的"小模型遗忘更严重"**只有方向性二手结论、没有可核实的实测数字**；
> 我们的 T2 恰好可以把它变成一个**可测量的贡献**（在小规模 LLM 上给出 stability-plasticity 曲线）。

> ⚠️ 这三项在 T1 会**逐项消融**：先只开第一项（证明"写得进"），再逐项加入（证明各项的必要性）。

## 4. 读取（Read）

- 查询 $q$ 进入上下文；记忆内容**不进入**。
- 所有 active 槽同时生效（$B_k A_k$ 相加），无需路由/检索步骤；T3 再试"按查询路由到少数槽"（稀疏激活）以降低串扰。
- **读取提示模板必须与写入时一致**（同一 `mem_prompt` 家族），否则退化为普通零样本问答。

## 5. 遗忘（Forget）

| 机制 | 作用对象 | 判据 | 备注 |
| --- | --- | --- | --- |
| **容量上限** | 全库 | 槽数 $K$ 硬约束 | 显式、可报告 |
| **效用淘汰** | 单槽 | 效用 $u_k$ = 该槽被成功召回次数 / 贡献度（留一法） | 需要读取统计 |
| **时间衰减** | 单槽 | $u_k \leftarrow \gamma \, u_k$，按"多少条写入"或"多少轮对话"计步 | 与真实时间解耦，便于复现 |
| **重要性保护** | 单槽 | 标记为"钢印"的槽不参与淘汰（如用户显式要求记住） | T2 可选加 |

淘汰 = **精确擦除**（§2），因此遗忘是可验证的，而不是"希望它淡了"。

## 6. 关键接口（T1 实现契约）

```
class MemoryStore:
    def write(self, item: MemoryItem, *, slot: int | None = None) -> WriteReport
    def read(self, query: str, *, active_slots: list[int] | None = None) -> str
    def forget(self, slot: int) -> ForgetReport          # 精确擦除
    def evict(self, policy: str, k: int) -> list[int]    # 按效用/时间淘汰
    def save(self, path) / load(path)                     # 跨会话持久化
    def slots(self) -> list[SlotMeta]                     # 槽位元数据（效用/时间/来源）
```

- `WriteReport`：本次写入的惊讶度、损失曲线、耗时 ms、峰值显存。
- 所有接口**不读上下文历史**（除写入时构造训练对所需的局部片段）——防止"偷偷用上下文"。
