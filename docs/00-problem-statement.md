## 1. 现象：LLM 的记忆只有一个可写通道，而它是零和的

今天让一个 LLM Agent"记住"事情，只有两条路：写进**上下文**（历史拼接、检索注入、记忆摘要），
或写进**参数**（微调 / 知识编辑，通常是离线、昂贵、离线的）。

只要不改变参数，**上下文就是唯一能写入的地方**，而这个通道有三个结构性缺陷：

| 缺陷 | 具体表现 | 后果 |
| --- | --- | --- |
| **零和** | 记住的 token 与推理用的 token 抢同一份预算 | 记忆越多，有效上下文越短 |
| **无差别驻留** | 上下文里的每段都同等"在场"，没有长期记忆 / 工作集的层级 | 噪声也占预算，且无法真正"遗忘" |
| **惯性 / 锚定** | 上下文里的内容被当成"正在发生的现实"而非"可调用的历史" | 话题跳转时被上文的主题、语气、**错误前提**拖拽 |

第 3 条是本项目认为最被低估的一条：**上下文记忆不仅占地方，它还甩不掉**。这里把"上下文惯性"操作化定义为：

- **I1 主题残留**：话题切换后，回答仍显著带上一话题的内容/词汇分布；
- **I2 前提继承**：上文给出的**错误前提**在切换话题后仍被当作事实使用；
- **I3 反复纠结**：回答重复解释已经结束的上文，而不是推进新任务。

## 2. 假设：记忆应当下沉到参数，并且要能遗忘

- **H1（可写）**：对话中获取的信息可以在**运行期**写入旁路参数，并在该信息**已离开上下文**后被读出。
- **H2（可忘）**：容量受限时，按效用/时间淘汰记忆，可以在保留重要记忆的同时清掉噪声，且基座能力退化可控。
- **H3（解惯性）**：参数记忆不进入上下文工作集 ⇒ 话题跳转时不被拖拽，惯性指标优于"把同样内容放进上下文"。
- **H4（划算）**：写入/读取的显存与时间开销，相对节省的上下文预算有净收益。

H1 是**技术前提**（做不成则后面全塌）；H2/H3 才是**卖点**；H4 决定它有没有工程意义。

## 3. 研究问题（RQ）

| RQ | 问题 | 对应假设 | 归因方式 |
| --- | --- | --- | --- |
| **RQ1** | 写进旁路参数的信息，在**上下文驱逐后**能否被正确读出？ | H1 | 适配器开/关对照 + 反事实写入（§见 02 文档协议 P2/P4） |
| **RQ2** | 容量受限下，效用淘汰 + 时间衰减能否"只忘该忘的"？ | H2 | 重要项 vs 噪声项的保留率差 + 基座能力探针 |
| **RQ3** | 参数记忆能否缓解上下文惯性/锚定？ | H3 | 三臂对照：无记忆 / 上下文记忆 / 参数记忆（I1–I3 指标） |
| **RQ4** | 净成本如何？（显存、写入延迟、token 节省） | H4 | 实测峰值显存、写入 ms/条、上下文 token 计数 |

## 4. 形式化设定

- 基座 $M_\theta$：**冻结**。$\theta$ 为 Qwen3-1.7B-Instruct 的全部参数。
- 旁路记忆 $\Delta$：一组低秩模块 $\{(A_i, B_i)\}$，作用于选定线性投影，等效权重 $W = W_0 + \frac{\alpha}{r} B A$。
- 交互序列：$x_1, \dots, x_T$。**记忆项** $m$ = 一个可陈述的信息单元（事实 / 偏好 / 经验教训 / 噪声）。
- 三个算子：
  - $\mathrm{Write}(\Delta, m) \to \Delta'$：运行期参数更新（本项目用梯度），**不经过上下文**；
  - $\mathrm{Read}(M_{\theta+\Delta'}, q)$：给定查询 $q$（$q$ 中**不含** $m$），输出答案；
  - $\mathrm{Forget}(\Delta', \mathcal{U}) \to \Delta''$：按效用集合 $\mathcal{U}$ 淘汰/衰减，容量 $|\Delta''| \le K$。
- 记 $\mathrm{ctx}(t)$ 为 $t$ 时刻上下文。**归因条件**：$\mathrm{Read}$ 时必须 $m \not\subseteq \mathrm{ctx}(t)$
  （严格定义与自检见 `02-metrics-and-isolation-protocol.md`）。

### 4.1 一个工程决定：记忆的容量单位 = LoRA 的秩块（slot）

低秩适配器是**稠密**参数，天生没有"条数"概念，无法干净地"删掉第 7 条记忆"。因此本项目采用
**秩块划分（rank-blocked / slot-partitioned LoRA）**：

- 总秩 $R = K \times r$（例如 $K=32$ 个槽、每槽 $r=4$ ⇒ $R=128$）；
- 第 $k$ 个槽 = 秩维度上的第 $k$ 个连续块；写入只用第 $k$ 块的梯度，其它块 `requires_grad=False`；
- **遗忘 = 把该块的 B 置零**（A 可保留作随机投影基）⇒ **精确、可验证、无残留**；
- 容量 $K$ 是**显式超参**，淘汰策略作用在槽上；每个槽可单独计效用、单独归因（哪条记忆在起作用）。

这样"遗忘"不再是软衰减的近似，而是**可证明的擦除**——这也是 RQ2 能做干净实验的前提。
（与既有工作的重合度由 `03-related-work.md` 核。）

## 5. 为什么现在做（一句话）

持续学习、测试时训练、记忆层、知识编辑四条线都已成熟到可以在**单卡 8 GB**上做受控实验，
但**"运行期写入 + 精确遗忘 + 上下文驱逐后可归因"这三件事同时成立**的验证，仍缺一份干净的实验结果。

## 6. 范围与非目标（诚实边界）

- **非目标**：训练一个通用的大模型记忆系统；不追求 SOTA 长对话成绩。
- **规模**：单卡 RTX 5060 Laptop **8 GB** ⇒ 基座固定 Qwen3-1.7B-Instruct + bf16 LoRA。
- **定位**：**机制验证 + 小规模受控实验**；规模可迁移性单独作为 limitation 讨论，不声称已证明。
- **数据**：不采集/不发布任何用户隐私对话；合成基准实体全部为**虚构**（见下）。

### 6.1 合成基准为什么要用"虚构实体"

若事实是"某真实人物的生日"，模型可能**凭预训练知识猜对**，我们就无法把正确率归因给参数记忆。
因此受控基准里的实体、属性、日期、地点**全部随机虚构**（如 `Velmora` 的首都是 `Trennick`），
并强制：
- 每个样本的值在预训练分布中**不可能出现**（自造词 + 随机数字组合）；
- 读取时的上下文**不含**该值，且不含任何可推断线索。
⇒ 答对**只能**来自参数记忆（或运气，由 P3 负对照估计运气水平）。

## 7. 与现有工作的关系

详见 `03-related-work.md`（三路文献侦察已回 A/B，C 进行中）。**必须正面回答的三类质疑**：

1. **"这不就是 O(1)/线性注意力的快权重吗？"** —— 与 Titans（arXiv:2501.00663）等的差异：
   我们**主干预冻结**、记忆载体是**显式槽位（可枚举、可单独擦除）**，而不是把记忆塞进 RNN 隐状态。
   Titans 是「attention=短期记忆 + neural memory=长期记忆 + 测试时学习 + 衰减遗忘」的最直接先例，
   related work 应排第一位。
2. **"这不就是知识编辑（ROME/MEMIT/AlphaEdit）吗？"** —— 差异：我们**运行期、无标签、增量、可淘汰**，
   且不动主干。其中 **AlphaEdit（ICLR 2025 Oral, arXiv:2410.02355）**的零空间投影可直接借用为
   写入时的"保护项"（见 `01-design.md` §3.1）。
3. **"长上下文足够强时还有必要吗？为什么不直接放上下文？"** —— ⚠️ **这条最难回答，必须给出实测而不是论断**：
   **RippleEdits（TACL 2024, arXiv:2307.12976）**的反直觉结论是"在 ripple 一致性上，
   **简单的上下文编辑基线得分最高**"。我们的主张（"下沉到参数省上下文、且免于上下文惯性"）
   必须用 §3.3 的三臂对照把它变成数据，否则不成立。

### 7.1 已经核实、必须写进定位表的三条工作

| 工作 | 结论 | 对本项目的影响 |
| --- | --- | --- |
| **WISE**（NeurIPS 2024, arXiv:2405.14768） | 终身编辑存在**不可能三角**：reliability / generalization / locality 不可兼得；其结构 = **main memory + side memory** | 我们的"主干 + 旁路记忆"与 WISE 同构 ⇒ 必须引用，且把"不可能三角"作为**评价框架**（三个维度一起报，不许只报一个） |
| **Merge before Forget**（arXiv:2512.23017） | 单 LoRA 持续合并 ⇒ 内存相对任务数**恒定**，但**一旦合并就无法撤销单条记忆** | 正面反衬我们的设计：**可撤销（可精确擦除）本身就是我们要保留的能力**，代价是容量受限 |
| **FADE**（arXiv:2604.27063, Schmidhuber 组, 2026-04） | 目前少数把**遗忘当一等公民**的工作；只作用于最后一层，**无现成代码** | 说明"可控遗忘"是**文献薄弱区** ⇒ 本项目的核心差异化就在 T2 |

### 7.2 我们打算占的那个缺口

分支 B 的核心结论：**防遗忘的文献极多，主动可控遗忘的文献极薄**；
并且找不到一篇能核实原文、在小规模 LLM 上给出 **stability–plasticity 实测数字**的论文。

⇒ 本项目的贡献定位调整为三件（按可辩护性排序）：

1. **可控遗忘 / 容量回收**（最强，文献最薄）：显式容量 $K$ + 效用/时间淘汰 + **精确擦除**，
   并给出「容量–保留率–基座漂移」三维曲线；
2. **归因方法论**（`02` 文档的 P1–P5）：任何人声称"参数记住了"都必须过这套协议；
3. **上下文惯性的量化**（新评测轴）：把"记忆不该占据工作集"从直觉变成指标。

> ⚠️ **记忆指标必须定义"召回之后改善了什么"**，不能只报命中率
> （语义缓存研究 arXiv:2608.20280 的教训：命中率 51–60% 而质量调整后只剩 1.1–2.2%，
> 且 18 个设定里没有任何淘汰策略比 LFU 好超过 0.041 个百分点 —— 淘汰策略的收益极易被高估）。
